# 桌面端（Tauri）打包与配置指南

记录将 OnePerson 法务工作台打包为 Windows 桌面应用（薄客户端）的架构、构建方式与踩坑经验，供后续换机器打包时参考。

> **打包模式：薄客户端。** Tauri 窗口直接加载服务器页面，不打包前端 dist，安装包仅 ~2.3 MB，核心功能依赖服务器在线。
> **服务器地址不写死在代码里**，首次启动由用户在应用内填写并保存在本地，之后换地址无需重新打包。

## 一、产物

| 文件 | 位置 | 大小 |
|------|------|------|
| 免安装主程序 | `src-tauri/target/release/oneperson-la.exe` | ~10 MB |
| NSIS 安装包 | `src-tauri/target/release/bundle/nsis/一人法务_0.1.0_x64-setup.exe` | ~2.5 MB |

构建命令（在仓库根目录执行）：

```powershell
$env:PATH = "$env:USERPROFILE\.cargo\bin;$env:PATH"
pnpm tauri build --bundles nsis
```

> `tauri.conf.json` 的 `bundle.targets` 已固定为 `["nsis"]`，不加 `--bundles nsis` 也只会打 NSIS。
> 不要改回 `"all"`，否则会额外尝试打 MSI（见坑 8）。

只出免安装 exe 不打安装包（更快）：

```powershell
pnpm tauri build --no-bundle
```

## 二、服务器地址配置机制（首次启动页）

### 设计目标

改服务器地址（内网 IP、frp 穿透域名等）**不需要重新打包**。

### 工作机制

```
启动
 ├─ 读 %APPDATA%\com.oneperson.la\config.json
 │   ├─ 有 server_url → 直接加载该地址
 │   └─ 无 / 读失败   → 加载内置配置页（setup:// 自定义协议）
 └─ 菜单「设置 → 修改服务器地址」→ 重新打开配置页（自动回填当前地址）
```

### 关键实现位置

| 位置 | 作用 |
|------|------|
| `src-tauri/src/lib.rs` | 读/写配置、`save_server_url` / `get_server_url` 命令、配置页 HTML、菜单 |
| `src-tauri/tauri.conf.json` | `app.windows` 置空（窗口在 Rust 中动态创建）；`app.withGlobalTauri: true` |

### 两个必须注意的点

1. **`withGlobalTauri` 必须为 `true`**
   否则配置页里拿不到 `window.__TAURI__`，`invoke` 不可用，页面会提示「当前环境不支持调用」。

2. **自定义协议在不同平台 URL 不同**
   - Windows：`http://setup.localhost/`
   - macOS / Linux：`setup://localhost/`

   窗口首次创建可用 `WebviewUrl::CustomProtocol(url)`（Tauri 会自动转换），但**后续 `navigate()` 必须传平台化的真实 URL**，否则跳转失败。

### 配置文件

```json
{ "server_url": "http://example.com:8080" }
```

路径：`%APPDATA%\com.oneperson.la\config.json`（由 `identifier` 决定）

## 四、踩坑与解决方案

### 坑 1：Rust 工具链反复损坏（missing manifest）

**现象**
```
error: missing manifest in toolchain 'stable-x86_64-pc-windows-msvc'
help: this may happen if the toolchain installation was interrupted
```

**根因**
多个 `rustup-init` 进程并发写同一 toolchain 目录（一个来自 winget，一个来自手动命令），互相覆盖导致 manifest 文件丢失。

**解法**
```powershell
# 停掉所有 rustup 进程
Get-Process rustup* | Stop-Process -Force
# 彻底卸载
rustup toolchain uninstall stable-x86_64-pc-windows-msvc
# 单进程重装
rustup toolchain install stable-x86_64-pc-windows-msvc --profile minimal
```

**预防**：不要在 winget 装 Rust 的同时手动跑 `rustup install`。

---

### 坑 2：rustup / cargo 下载极慢或卡住

**现象**
`rustup toolchain install` 长时间无输出；`cargo build` 卡在 `Updating crates.io index`。

**根因**
`static.rust-lang.org` 和 `crates.io` 国内访问不稳定。

**解法**：用镜像源。

**Rust 工具链镜像**（装 rustup 时设置环境变量）：
```powershell
$env:RUSTUP_DIST_SERVER  = 'https://rsproxy.cn'
$env:RUSTUP_UPDATE_ROOT   = 'https://rsproxy.cn/rustup'
rustup toolchain install stable-x86_64-pc-windows-msvc --profile minimal
```

**cargo 依赖镜像**（写入 `%USERPROFILE%\.cargo\config.toml`）：
```toml
[source.crates-io]
replace-with = "rsproxy-sparse"

[source.rsproxy-sparse]
registry = "sparse+https://rsproxy.cn/index/"

[net]
git-fetch-with-cli = true
```

**Tauri 打包时下载 NSIS 失败**：`github.com` 不可达，用 `gh-proxy.com` 代理：

```
https://gh-proxy.com/https://github.com/tauri-apps/binary-releases/releases/download/nsis-3.13/nsis-3.13.zip
```

---

### 坑 3：MSVC Build Tools 安装器「进程一会就没了」

**现象**
`vs_BuildTools.exe --quiet` 启动后几秒就退出，`link.exe` 一直没出现。

**根因**
安装器是终端的**子进程**。下一条 shell 命令执行时会占用同一终端，子进程被连带终止（退出码 `0xC000013A`）。

**解法**：用 WMI 脱离终端启动，或直接手动运行安装程序。

```powershell
# 方法 A：WMI 创建独立进程
$cmd = '"<path>\vs_BuildTools.exe" --quiet --wait --norestart --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended'
Invoke-CimMethod -ClassName Win32_Process -MethodName Create -Arguments @{ CommandLine = $cmd }

# 方法 B（推荐）：手动双击安装，GUI 里只勾「使用 C++ 的桌面开发」
```

验证安装成功的标志：
```
C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Tools\MSVC\<版本>\bin\Hostx64\x64\link.exe
```

---

### 坑 4：NSIS 解压反复报「拒绝访问 (os error 5)」

**现象**
```
Info extracting NSIS
failed to bundle project: `拒绝访问。 (os error 5)`
```

手动用 `Expand-Archive` 解压到 `%LOCALAPPDATA%\tauri\NSIS` 却正常。

**根因**
**后台模式（`run_in_background`）下，关闭沙箱并未真正生效**，沙箱仍拦截对 `%LOCALAPPDATA%` 的写入。

**解法**：改用**前台同步**执行（不设后台运行）。

```powershell
$env:PATH = "$env:USERPROFILE\.cargo\bin;$env:PATH"
pnpm tauri build --bundles nsis 2>&1 | Select-Object -Last 12
```

---

### 坑 5：`link.exe not found` 但 MSVC 目录存在

**现象**
```
error: linker `link.exe` not found
```
但 `C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Tools\MSVC\14.44.35207\` 目录存在。

**根因**
Build Tools 安装被中断（见坑 3），只装了目录结构，核心编译器组件（`link.exe`、`cl.exe`）没落地。

**解法**：重新完整安装一次（用坑 3 的方法），确认 `bin\Hostx64\x64\link.exe` 存在。

---

### 坑 6：pnpm 安装依赖报 `ERR_PNPM_EPERM`

**现象**
```
ERR_PNPM_EPERM Failed to add tarball to store: EPERM: operation not permitted,
open 'D:\.pnpm-store\v10\files\...'
```

**根因**
pnpm 全局 store 配置在 `D:\.pnpm-store`，而该路径不在当前环境的可写白名单内。

**解法**：在沙箱外执行，或将 store 改到项目内：

```powershell
pnpm config set store-dir "D:\vibe_coding\OnePerson_LA\.pnpm-store"
```

---

### 坑 7：配置页点「保存」没反应 / 提示不支持调用

**现象**
配置页能显示，但点击保存报「当前环境不支持调用，请在桌面应用内打开」。

**根因**
`tauri.conf.json` 未开启 `app.withGlobalTauri`，`window.__TAURI__` 为 `undefined`。

**解法**
```json
"app": { "withGlobalTauri": true }
```

另外 Tauri 2 中全局对象路径有变化，取值需兼容：
```js
var tauri = window.__TAURI__ || {};
var invoke = tauri.core ? tauri.core.invoke : tauri.invoke;
```

---

### 坑 8：构建「卡住」——编译完成后一直无输出

**现象**

终端停在 `$env:PATH = ...; pnpm exec tauri build` 之后，只有一行 `cargo 1.99.1`，几十分钟没有任何新输出，看起来像卡死；但 `target/release/oneperson-la.exe` 的修改时间是新的（Rust 其实已经编译完）。

**两个叠加原因**

1. **`bundle.targets` 为 `"all"`**：Rust 编译完后会继续打 MSI，MSI 需要下载 WiX 工具链（github.com），国内不可达，于是无限期挂起。
2. **管道 `| Select-Object -Last N` 会缓冲全部输出**：命令没结束前一行都不显示，把「正在下载 WiX」的等待误判成死机。

**解法**

- `tauri.conf.json` 固定 `"bundle": { "targets": ["nsis"] }`（或命令行加 `--bundles nsis`），只打 NSIS，不需要 WiX。
- 观察进度不要用 `Select-Object -Last`，改成 `Tee-Object -FilePath build.log`，随时可看日志尾部。
- 已经挂起的进程直接结束，重新跑一次即可（cargo 有增量缓存，通常 1 分钟内完成）：之前构建成功的 NSIS 是 22:10，挂起那次编译产物是 22:47，可据此判断卡在哪一步。

```powershell
$env:PATH = "$env:USERPROFILE\.cargo\bin;$env:PATH"
pnpm tauri build --bundles nsis 2>&1 | Tee-Object -FilePath build.log
```

## 五、日常更新是否需要重新打包

| 变更类型 | 需要重打包 | 说明 |
|----------|:----------:|------|
| 前端页面 / 后端接口 / 数据库结构 | ❌ | 服务器部署即可，客户端重开即最新 |
| 更换服务器地址 / 域名 | ❌ | 应用内「设置 → 修改服务器地址」 |
| 窗口尺寸、标题、菜单 | ✅ | 改 `tauri.conf.json` |
| 新增原生能力（托盘、通知、文件系统） | ✅ | 改 `lib.rs` 与依赖 |
